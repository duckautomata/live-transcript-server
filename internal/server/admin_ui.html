What each part of this page shows

Worker
The transcription worker assigned to this channel. Online means it has reported its status within the last 5 minutes; the line below shows its version and when it last checked in. Offline usually means the worker process is down or can't reach the server.
Discord bot
The server-side bot that watches Discord for stream announcements and queues them automatically. Online (green) means its connection to Discord is healthy and this channel's announcements will be picked up. Reconnecting (amber) means Discord has gone quiet and the server is re-establishing the connection. Offline (red) means the connection is down - the reason is shown below the status, and announcements are missed until it recovers, so queue URLs by hand in the meantime. Off (gray) means no bot is configured on this server at all. An amber dot next to Online flags a configuration problem (for example, this channel has no announcement name mapped) even though the bot itself is healthy.
Connected clients
How many viewers currently hold a live WebSocket connection to this channel's transcript page. Clients connecting or disconnecting don't trigger an instant update - this count refreshes about once a minute.
Server
The version and build time of the transcript server itself (this backend, not the worker).
Streams
Every stream stored for this channel. Live means the worker is transcribing it right now; Past means it has ended. Each row shows the title, the stream ID, when it started, and what kind of media was captured. Edit corrects any of those details, and Full VOD builds (or downloads) the whole stream as one file - see the cards below.
Incoming queue
Stream URLs waiting for the worker. The worker takes a URL out of the queue when it picks it up; Remove takes one out by hand before that happens. The form at the bottom queues a new URL.
Worker controls
The Restart and Stop signals for the worker, plus a badge showing whether a restart is pending. See the “Restart vs. Stop” card below for what each one does.
Notifications (tab)
Announces this channel's streams, scheduled streams, uploads and shorts to Discord, driven by the server's own live detection. Create notification events that post to your webhooks with a custom message, role pings and embed; watch what was delivered; and see how detection itself is doing. See the “Notifications” card below.
Membership keys (tab)
Only shown when this channel has membership configured and the archive server is reachable. Manages the keys that gate members-only content - see the “Membership keys” card below.

Queue, stream, and restart changes show up within a second or two - no need to reload. The connected-client count, the worker's last-seen time, and the Discord bot status are the exception: they refresh about once a minute, plus whenever you perform an action or return to this tab.

Start a stream (queue it)

  1. Paste the full stream URL (e.g. https://twitch.tv/… or https://www.youtube.com/…) into the input at the bottom of the Incoming queue card and click Add.
  2. The worker is notified within seconds. As soon as it isn't busy with another stream, it takes the URL from the queue and starts capturing.
  3. The stream then appears in Streams with a Live pill once transcription begins.

Adding a URL that's already queued just re-queues it - no duplicates. If the worker is offline, the URL simply waits in the queue until the worker comes back.

Delete a stream

Past (inactive) stream:

  1. Click Delete on its row in the Streams card.
  2. In the confirmation, choose whether to also delete its media files (kept by default - see the next card).
  3. Confirm. The stream and its transcript are removed from the server, and connected viewers drop it immediately.

Live (active) stream: the Delete button is disabled while a stream is live - the worker would just re-create it on its next push. Instead:

  1. Click Stop current stream under Worker controls and confirm.
  2. Wait for the stream's pill to flip from Live to Past - typically a few seconds; the page updates on its own.
  3. Delete it like any past stream.

Delete media from a stream

Media (the audio, video, clip, and frame files in storage) is deleted together with its stream - there is no separate media-only delete.

  1. Click Delete on the stream's row.
  2. Tick “Also delete media files from storage” in the confirmation dialog.
  3. Confirm - the stream's entire storage folder is permanently removed.

Left unticked (the default), only the stream record and transcript are deleted; every media file stays in storage.

Edit a stream's details

Edit on a stream's row corrects what the server recorded about it. Details come through wrong often enough to need it - a bad title or start time from the platform, a worker that fell back to its own clock, or a stream left marked live because its worker died before saying so.

Title
What viewers see, and what appears in stream notifications. Leave it empty to show “(untitled)”.
Start time
Everything a viewer sees is timed against this. Enter it in your own local time - the server is told the exact moment, so admins in other time zones make the same correction.
Media type
video allows mp4 clips and mp4 VOD renders, audio is audio-only, and none means no media was captured. Setting this wrong is what makes clipping refuse a stream that does have video.

Any stream can be edited at any time, live or ended. Only the fields you actually change are sent, and the moment you save, every connected viewer is told to update - no reload, no waiting for a reconnect. The change is logged to the admin audit webhook with the old and new value of each field.

Three things are deliberately not editable here. The stream ID is what the stream's media and transcript are filed under; its position in this list comes from when it was first activated; and whether it is Live belongs to the worker - use Stop current stream under Worker controls to end a capture. Editing a live stream is allowed, but the worker may overwrite what you set the next time it resyncs, so it's worth redoing once the stream has ended.

Download the full VOD

Every stream is captured as thousands of small chunks. Full VOD stitches all of a stream's chunks back into one file - .mp4 for video streams, .m4a for audio-only ones.

  1. Click Full VOD on a Past stream's row. The button is disabled while a stream is Live: the recording is still growing, so a VOD built now would stop partway through. Stop the stream first and wait for the Past pill.
  2. Confirm in the dialog. It tells you how many chunks will be stitched and warns you if any part of the stream is missing.
  3. The build runs on the server in the background - minutes for a long stream. The row shows what it's doing (merging chunks → encoding → uploading) and the button says Building…. You can leave the page open, or come back later and press the button again to pick the file up.
  4. When it's done the button turns into Download VOD. Pressing it confirms that the file is ready, and saves it as soon as you accept.

Only one copy is ever built. If several admins press the button at once, they all join the same build instead of each starting their own, and a stream that already has a VOD hands the existing file straight back rather than rebuilding it.

If the row says some lines have no media, those parts of the stream were never captured (a worker restart, a failed upload) and the VOD skips straight past them - everything else is still included. The finished file lives alongside the stream's other media, so deleting the stream with “Also delete media files” removes it too.

Worker controls: Restart vs. Stop

Restart worker
Sets a flag the worker reads on its next poll, making it drop whatever it's doing and recycle. The incoming queue is untouched, so anything queued gets picked right back up. Use this to un-stick a misbehaving worker.
Stop current stream
Clears every URL from the incoming queue and sets the restart flag. The worker drops the current stream and then sits idle, since nothing is left to pick up. Use this to end a capture on purpose - and as step one of deleting a live stream.
Restart pending / Cancel
While a restart is waiting for the worker, the card header shows Restart pending with a Cancel button. Cancel withdraws the request if the worker hasn't acted on it yet; the badge clears on its own once the worker restarts.

Notifications

The server watches this channel's YouTube and Twitch accounts itself (no Discord bot needed) and, when it sees something new, runs every notification event you have created. Each event is a rule: when any of these triggers fires, post this message and embed to these webhooks.

Triggers
Going live covers a Twitch stream starting, a YouTube stream starting, and a YouTube premiere beginning. Stream or premiere scheduled fires when a waiting room or premiere page appears. Video uploaded and Short uploaded fire when a regular video or a short is published. An event can react to any mix of them.
Webhooks
One event can post to several Discord channels: add a webhook per channel. Create webhooks in Discord under the channel's settings → Integrations → Webhooks. Only Discord webhook URLs are accepted, and nothing except a rendered announcement (or a test you send yourself) is ever posted through them - no errors, no diagnostics.
Message and role pings
The message is the text above the embed and is where role pings go. Type the role's ID into the helper and click Insert role ping, or write <@&ROLE_ID> by hand. To find a role ID: turn on Developer Mode (User Settings → Advanced), then Server Settings → Roles → ⋯ → Copy Role ID. Placeholders such as {channel}, {title} and {url} are filled in when the notification is sent - click one in the editor to insert it.
Embed
The card under the message, with a title, description, color, image and footer - each a template too. It starts out looking like the server's own stream-start post; Reset embed to the default look gets that back. Untick Include an embed to send text only.
Minimum time between notifications
After the event posts for a trigger, it stays quiet for that trigger for this long. A stream that drops and restarts is a brand-new broadcast to the platform and would otherwise ping everyone again; 30 minutes swallows that while still announcing a second stream later in the day. Because the gap is per trigger, a “scheduled” ping never eats the “going live” ping that follows it. Suppressed pings are listed under Recent deliveries so you can see the limit working.
Preview and Send test
The preview on the right of the editor is rendered by the server from this channel's most recent detection for the trigger, so it is exactly what would be posted; anything that detection lacked (a title, a start time) is left blank rather than made up, and a channel with nothing detected yet previews blank details. Send test… posts that rendering to a webhook of your choice with every ping suppressed - role mentions appear as text and nobody is notified - so you can check the look in a real channel, or in a private one, before enabling the event.
Recent deliveries
Every decision the server made: Sent, Partial (some webhooks failed - the detail says which and why), Failed, Suppressed by the minimum gap, or a Test you sent. A webhook that was deleted in Discord shows up here as a failure with “webhook no longer exists”.
Live detection cards
Live detection summarises the health of the detection legs (Twitch EventSub and polling, YouTube WebSub, state polling and discovery); the legs card lists each one. Worker queue says whether a detected stream is queued for the worker automatically (liveDetect.queueIncoming in the server config) or only announced. Operator feed is the server's own copy of every detection, posted in the default look with no pings to discord.detectWebhookUrl - the same feed that carries detection problems, kept separate from the audience webhooks on purpose.

Membership keys

The Membership keys tab appears only when this channel has membership configured and the archive server is reachable. Keys gate access to this channel's members-only content on the archive server.

Generate new key
Creates a key on the archive server and copies it to your clipboard. The archive keeps at most 2 keys per channel, so generating a third silently removes the oldest. To rotate: generate a new key, hand it out, and let the old one get pruned by the rotation after that.
Copy
Copies that row's key to the clipboard. Each row also shows when the key expires.
Delete all keys
Removes every key for the channel at once - there is no per-key delete. Anyone using one of the keys loses access immediately.

Login & the admin key

“Save key in this browser” keeps the key in this browser's local storage so you skip the login next time on this device - leave it unchecked on shared computers. Logout forgets the saved key and returns to the login prompt.
